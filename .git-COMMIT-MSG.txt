sdk: port the c grammar to queries - priority splits prototypes from state

The trial's one STRETCH is dead: a declaration whose declarator is a
function_declarator is a PROTOTYPE (a function unit, honest under the
function noun); any other declaration is state. The split is stated
with @priority directives in queries.scm and enforced at load.

New seams (round-5 review):

- PATTERN-ORDER VALIDATOR: two patterns rooting on the same node type
  with different captures must state intent (an "; @priority" comment
  on one pattern of the conflicting group) or the run fails at setup
  naming the patterns - an agent reordering patterns gets an error,
  not silence. Root type over-approximates (two patterns may never
  match the same node); forcing the one-line statement is the point.
- MANIFEST POLICY OVERRIDES: policy: { <capture>: { opaque, absorbTail },
  selfNesting } in <lang>.manifest.json overrides the capture policy
  table per grammar; sameCaptureNesting is folded into that home and
  gone as a separate field. Absent policy = table defaults (zero
  config). md declares policy.selfNesting; no other grammar needed an
  override in practice.
